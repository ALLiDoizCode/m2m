# Runbook — shepherding the #409 epic (connector rewrite)

Repo: `toon-protocol/connector`. Working dir: `/home/jonathan/Documents/connector`.
Parent epic: **#409** (label `tracking`, never close or edit it).

`main` has **no branch protection** and all merge methods are allowed, so CI green is the only
gate that exists. Merge with **squash** (`gh pr merge --squash`), matching the repo's history
where the PR number is appended to a conventional-commit subject.

`gh` on this repo intermittently fails on plain porcelain reads. Always read with
`--json <fields>`, and **verify every write landed** by reading it back.

## Each pass

**1. Unblock.** For every open issue in 410–431 that does not already carry `agent:implement`:
if all of its blockers are closed, add the label. Verify it landed. Never label an issue whose
blockers are still open — a bot with no foundation to build on produces a bad PR.

**2. Merge what is ready.** For every open PR, work out which ticket it implements (title, branch
name, or a closing reference in the body). Merge it with squash when **all** of these hold:

- every check has concluded and none failed
- `mergeable` is true and `mergeStateStatus` is not `DIRTY` / `BLOCKED`
- the blockers of the ticket it implements are all closed
- it is not a draft

Merge in dependency order: if two PRs are ready and one implements a blocker of the other, merge
the blocker first. After merging, re-check the remaining PRs — a merge can turn another PR dirty.

**2a. Serialise conflicts on a shared crate.** Several tickets fan out from one parent and land in
the same crate, so each merge dirties the others. Do not file a rebase ticket while another PR is
about to merge into the same files — the rebase would target a `main` that is about to move, and
the work is thrown away.

Before filing any rebase ticket, check whether a currently-mergeable PR touches the same paths the
conflict is in. If it does, **merge that PR first and file the rebase ticket afterwards**, against
the settled `main`. Rebase one dirty PR at a time; re-check the rest after each merge. It is
better for a dirty PR to sit for one cycle than to be rebased twice.

**3. File fix tickets.** When a PR has failed checks or a conflict, and no open fix ticket already
exists for it, create one issue with `agent:implement`:

The runner is branch-per-issue: given a fix ticket it creates `sandcastle/issue-<fix>` and opens
a **new** PR, rather than updating the branch you named. That is fine — the new PR supersedes the
old one — but it must be told to say `Closes #<original epic ticket>` in its body, or the epic
ticket stays open after the merge and everything downstream of it stalls. Close the superseded PR
once its replacement merges.

- title: `fix: <what is broken> (PR #<n>)`
- body: which PR, which ticket it implements, the failing job or the conflicting paths, and the
  actual error output — enough that a fresh agent can act without re-investigating
- do not close or relabel the original ticket

Do not file a duplicate on a later pass. Check for an existing open issue mentioning that PR
number first.

**4. Report.** One short status line: which tickets were unblocked, which PRs merged, which fix
tickets were filed, and how many of 410–431 remain open.

## Notify the human

Merging green PRs is unattended. Judgement is not. Send a **PushNotification** (load it with
ToolSearch first) — one short line, plus detail in the pass report — whenever any of these
appears. Do not batch these to the end of the epic; send them when they happen.

- **A PR diverges from an ADR or from its ticket's acceptance criteria** while still being green.
  CI cannot see this. The first PR of the epic silently renamed five crates away from ADR 0001,
  and only a read of the diff caught it.
- **A PR changes the money path** — claim signing or verification, watermarks, settlement,
  redemption, the journal, the signer, or the treasury. Merge it if green, but say so.
- **A ticket's acceptance criteria cannot be met as written**, or a PR closes a ticket while
  visibly leaving a criterion unsatisfied.
- **The same PR fails twice with the same error.** Stop filing fix tickets for it and hand it over.
- **Anything touching the deployed contract, the peer wire specification, or #431** (the devnet
  cutover).
- **Anything outside the #409 tree**, which is never merged or modified by this loop.

Everything else — routine green merges, routine unblock-labelling, first-time CI failures with a
fix ticket filed — needs no notification and belongs in the pass report only.

## Stopping

When every issue in 410–431 is closed, report that the epic is complete and **end the loop**.
Do not close #409 — that is the human's call.

## Boundaries

- Never force-push, never close a ticket by hand, never edit #409.
- Never merge a PR whose ticket still has an open blocker, even if the PR is green.
- If a PR touches something outside the #409 tree, leave it alone and say so in the report.
- If the same PR fails twice with the same error, stop filing tickets for it and flag it for a
  human instead.

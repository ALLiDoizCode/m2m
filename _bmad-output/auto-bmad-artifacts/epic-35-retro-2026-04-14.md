## Challenges

### 1. No real-binary ATOR integration test in CI

The real ATOR client binary is tested only via manual nightly runs that were **deferred**. All in-CI integration tests use mocks or stubs. This repeats the Epic 34 pattern (proof-enabled Mina tests deferred) and is the largest verification gap in Epic 35. The managed lifecycle (35.5) in particular has never been verified end-to-end against a real ATOR process in an automated pipeline.

### 2. Optional dependency has no `npm audit` gate

`@anyone-protocol/anyone-client` being optional means it escapes the standard audit pipeline. For a transport privacy dependency, this is the wrong shape of gap -- privacy-critical third-party code should receive **more** scrutiny, not less. No CVEs were identified in this epic, but the gate itself is missing.

### 3. AC #9 in Story 35.6: BTP-vs-ILP scope compromise

Story 35.6's AC #9 was scoped down during implementation to test at the BTP layer rather than the full ILP layer. NFR was marked CONCERNS-mergeable with a documented rationale. This is defensible for the immediate scope but means a class of integration behavior is covered less rigorously than originally planned.

### 4. Fragile test reaching into `BTPClient._ws` private state

INT-04 pokes a private field (`_ws`) to simulate connection states. This works today but will break on any internal refactor of BTPClient and gives no compiler help when it does. Known fragility, not fixed.

### 5. `externalUrl` defaults to `ws://localhost` placeholder

The default `externalUrl` is `ws://localhost`, which is semantically wrong for any real deployment. Operators **must** override it. The docs (35.7) note this, but a deploy-time check or a required field would be a stronger guardrail than documentation.

### 6. 30-second health-cache granularity

The ATOR health check caches for 30s. For an overlay transport where bootstrap can stall for minutes, 30s is both too long (if something is wrong, feedback is sluggish) and too short (if everything is fine, the cache adds little value beyond a smaller window). This was accepted as sufficient for now but flagged as a likely tuning target.

### 7. Pre-existing path-join triage at `connector-node.ts:1720`

Surfaced during code review, confirmed pre-existing (not caused by this epic), and left in place. Carrying unresolved pre-existing issues across epics obscures ownership.

### 8. Docs-drift CI gate is missing (MEDIUM)

Story 35.7 shipped docs, but there is no CI gate that fails when config schema (35.3) and docs (35.7) drift apart. Given that Zod schemas and markdown references live in separate files, future drift is near-inevitable without automation.

### 9. Zod migration debt carried in

The codebase is partway through a Zod schema convention migration. Story 35.3 added new config blocks that technically comply but reinforce the mixed pattern rather than complete the migration.

## Key Insights

### 1. Transport is a clean abstraction boundary for ILP connectors

`TransportProvider` slotted into the existing BTP/ConnectorNode layering without disturbing settlement or packet-handling code. This confirms the connector's architectural seams are appropriately placed: settlement (Epics 32-34) and transport (Epic 35) are orthogonal concerns that do not cross-contaminate.

### 2. "Managed" subsystem lifecycle is a reusable pattern

Story 35.5's managed ATOR client lifecycle (spawn, health check, readiness gate, shutdown) generalized well and is the same shape of lifecycle the Mina lightnet Docker and Solana test-validator subsystems use. Extracting a reusable `ManagedSubsystem` primitive is a candidate for a future epic.

### 3. Optional dependencies need their own security posture

Optional deps currently bypass the audit pipeline simply because they are not `dependencies`. The decision "should we install it?" and the decision "should this version be trusted?" are separate; the current tooling conflates them.

### 4. Privacy features require explicit AC-level coverage

Privacy properties (no IP leakage, DNS via proxy, connection isolation) do not emerge from functional tests -- they must be asserted directly. Epic 35's explicit AC-level privacy coverage is the right pattern and should propagate to any future privacy-adjacent feature.

### 5. Config schema + docs drift is a real risk class

Having config validated by Zod (35.3) and documented in markdown (35.7) without a generated or cross-checked link means every future config change has two places to update. This is exactly the shape of drift that automation should prevent.

### 6. Defensible-by-design "Low" findings accumulate

Three of Epic 35's Low findings were closed as "defensible-by-design." Across epics these add up. A periodic sweep to either suppress them formally (with a noqa + rationale) or address them is better than re-evaluating them each review cycle.

### 7. Deferring integration tests repeatedly has compounding cost

Mina proof-enabled tests (Epic 34) and ATOR real-binary tests (Epic 35) are both deferred to "nightly that doesn't exist yet." The longer the deferred list, the larger the effort to stand up the nightly infrastructure that would run them all.

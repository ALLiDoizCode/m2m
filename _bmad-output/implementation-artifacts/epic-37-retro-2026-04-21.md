## 2. What Went Well

1. **Pattern reuse over invention.** 37.1 used the existing `btpClientManager.getPeerIds()` guard (already in `/admin/peers` DELETE/PUT) rather than inventing a parallel peer registry. Consistency over cleverness.
2. **Contract locked before code.** The cross-team response doc was referenced as authoritative in every story. §9.2 Q-numbers appeared in dev notes. Shape known before implementation.
3. **Adversarial review worked on 37.3.** ~10 findings, including reversal of the author's own dev-note reasoning (D1: "defensive union" flipped to "drop removed peers immediately"). O(n²) lookup caught. Runtime `registerPeer`/`unregisterPeer` miss caught.
4. **Dependency injection of the metrics registry** (37.2 dev note) — `_ilpMetrics` became a testable field on `ConnectorNode` rather than a module-level side effect.
5. **Docker-image verification as an explicit AC** (37.2 AC 6) — not "ran tests locally, looks good" but "built the image, curl'd `/metrics`, saw the counter family." This is the pattern to generalize.
6. **Inline review decision log** — `[x]`/`[ ]` findings with decision IDs (D1, D2) embedded in the story file. Durable artifact future readers can learn from.

## 3. What Didn't Go Well

### Systemic themes

| Theme | Evidence |
|---|---|
| **Parallel-surface drift** | 37.1 (balances vs. peers 404 semantics), 37.3 (`/metrics` vs. `/metrics.json` peer visibility) |
| **Missing end-to-end HTTP-surface tests** | `/metrics` was a 404 in every deployed image since inception; undetected by us — Town's T-020 caught it |
| **Deferral loopholes** | 37.3 tasks 5/6/8 deferred to a "documentation epic" that does not exist in `planning-artifacts/` |
| **Retro discipline slipping** | Epic 36 retro still `pending`; Epic 37 retro is implicitly double-duty |

### Specific issues

1. **The `/metrics` empty-middleware slot shipped for the entire history of the project.** The fix landed in 37.2, but the detection gap is the real problem. We had an HTTP route and never wrote a test that curled it and asserted a non-empty response.
2. **Runtime peer add/remove did not update the metrics registry** on 37.3. `/metrics.json` was saved by the `getPeerIds()` union fallback; Prometheus `/metrics` would have omitted runtime-added idle peers until first packet. Caught by review, not implementation.
3. **D1 reversal mid-review on 37.3.** Original dev note defended "defensive union of `getPeerIds()` and counter labels." Review reversed: drop removed peers immediately. Lesson: when a degraded-state UX decision is on the table, reason asymmetrically about failure modes — which one does the user notice and hate more?
4. **O(n²) peer lookup** (`peerSnapshots.find(...)` inside `.map()`) — minor at N≤10 peers but a pattern worth flagging. Caught in review.
5. **Test mock drift** — `getPeerStatus()` mock didn't include all peers from `getPeerIds()`, over-exercising the `connected:false` fallback.
6. **Commit hygiene** — 37.1's balances 404 guard appears to have been committed together with 37.3's work; needs manual split for clean git history.
7. **Documentation debt deferred to a non-existent epic.** Tasks 5/6/8 on 37.3 say "Deferred: Documentation epic planned" — no such epic file exists. Handoff to nobody.
8. **Epic 36 retro skipped.** Sprint-status shows `pending`; no retro file on disk. Breaks the practice.

## 4. Key Insight — Parallel-Surface Drift

Both of Epic 37's substantive issues trace to the same root cause: **multiple HTTP endpoints expose overlapping projections of the same underlying state, and we have no mechanism to enforce they agree.**

- 37.1: `/admin/balances/:peerId` and `/admin/peers` both make implicit claims about which peers exist. They disagreed on "unknown peer" semantics.
- 37.3: `/metrics` (Prometheus) and `/admin/metrics.json` both project per-peer counters. They disagreed on runtime-added idle peer visibility.

**Cross-surface invariant tests** (peer added via `POST /admin/peers` must appear in every endpoint that projects peer state) are the structural antidote. This is the headline motivation for Epic 38.

## 7. Significant Discovery — Epic 38 Required

**Significant change flag: YES.** Epic 37's retro surfaced that the absence of comprehensive HTTP-surface e2e testing is a systemic detection gap, not a per-epic oversight. This is the headline deliverable of this retrospective.

### Epic 38 scaffold (to be authored next)

**Title:** Comprehensive HTTP Surface E2E Test Coverage

**Goal:** Every HTTP endpoint the connector exposes is exercised end-to-end against the real `Dockerfile`-built image with real peers, real packet flow, and real dependencies. Cross-surface invariants are asserted so parallel-surface drift is impossible to ship undetected.

**Scope decisions locked with Jonathan during this retro:**
- **1(b)** Comprehensive HTTP-surface coverage — new test file `admin-api-surface-e2e.test.ts` built on an endpoint inventory doc.
- **2(i)** Nightly CI gating, opt-in on feature branches. Enforced by AG3.
- **3(x)** Drafted as Epic 38 in `planning-artifacts/` (not left as a retro action item).

**Proposed stories:**

| Story | Title | Size |
|---|---|---|
| 38.1 | HTTP endpoint inventory doc (`docs/admin-api-inventory.md`) — every route, auth model, contract | S |
| 38.2 | `admin-api-surface-e2e.test.ts` — asserts every endpoint in the inventory returns a sane response against the `standalone-container-e2e` topology | M |
| 38.3 | Cross-surface invariant tests — peer added via `POST /admin/peers` must appear in `/admin/peers`, `/admin/balances/:peerId`, `/metrics`, `/metrics.json` | M |
| 38.4 | Packet-flow observability invariants — after N ILP PREPAREs flow, counters in `/metrics` match `/metrics.json` match aggregate | S |
| 38.5 | Nightly CI workflow for the HTTP-surface e2e suite — stop-the-line policy documented | S |
| 38.6 | Backfill: add `standalone-container-e2e` assertions for `/health` and any endpoints missed by 38.1 inventory | S |

**Done when:**
- Every route in `docs/admin-api-inventory.md` is called by an e2e test against the built image.
- Cross-surface drift between any two endpoints exposing overlapping state is asserted impossible.
- Nightly CI runs the suite; failures trigger a documented stop-the-line response.
- AG2 is structurally enforced (CI), not just a team agreement.

**Infrastructure leverage:** `packages/connector/test/integration/standalone-container-e2e.test.ts` already boots the `Dockerfile` image with two connectors, a BLS, BTP between them, and real packet flow. Epic 38 extends — not replaces — this harness.
